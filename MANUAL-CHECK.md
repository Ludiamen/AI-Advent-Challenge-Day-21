# Ручная проверка Дня 21 в браузере

Сценарий для проверки руками: **индекс документов** (День 21). Документы
организации — договоры (текстовый PDF и сканы) и бюджетные таблицы Excel —
режутся на чанки двумя стратегиями, для каждого чанка локальная модель bge-m3
считает вектор, и всё ложится в `index/docs.db` вместе с паспортом чанка.
Страница `/rag` собирает индекс, ищет по нему двумя стратегиями рядом,
показывает чанк с границами соседей и сравнивает стратегии числами. Части 4–11
— регрессия: оркестровка Дня 20 и всё, что было раньше.

Каждый шаг устроен одинаково: **что сделать** → **что должно получиться**.

Время: около 40 минут (без первой сборки индекса). Вызовов модели: 5–7. В шапке выберите модель
**DeepSeek V4 Flash (ds-flash)**: она отвечает быстро и уверенно пользуется
инструментами.

Сценарий пройден в браузере (headless Chrome, порт 5001) на живом моке трекера
и живой модели: ожидания ниже — то, что происходит на самом деле.

Есть и второй вариант того же пути — [DEMO-CHROME.md](DEMO-CHROME.md): тот же
день, но сценарий написан для браузерного расширения Claude in Chrome и разбит
на семь сцен под запись экрана. Этот файл — для человека, тот — для показа.

## Часть 0. Подготовка

Понадобятся **два терминала**.

```bash
# терминал 1 — страница
cd ~/Документы/AI-Advent-Challenge/Day-21
python3 -m venv .venv
.venv/bin/pip install -r requirements.txt     # Flask, httpx, MCP SDK, numpy, openpyxl, pypdf
cp -n .env.example .env                       # если .env ещё нет
mv memory memory-до-проверки 2>/dev/null || true
rm -rf reports                                # чтобы было видно, что файлы новые
.venv/bin/python cli.py --индексировать       # один раз: OCR сканов + векторы bge-m3 (≈ час на CPU)
.venv/bin/python web.py
```

```bash
# терминал 2 — API, вокруг которого построен инструмент Дня 17
cd ~/Документы/AI-Advent-Challenge/Day-21
.venv/bin/python tracker_api.py --сброс       # 127.0.0.1:8766, данные заново
```

Откройте `http://127.0.0.1:5001`.

- [ ] Заголовок страницы: «Агент миграции ГИС — индекс документов (RAG)».
- [ ] Сверху синяя карточка «Новое в Дне 21 — индекс документов» со ссылкой
      «Индекс документов →» и сводкой «собрано: «фикс» N чанков, «структура» M
      чанков (ollama:bge-m3)».

Для индекса нужны ещё две программы, обе ставятся один раз:
`sudo apt install tesseract-ocr tesseract-ocr-rus` (OCR сканов) и Ollama с
моделью `bge-m3` (`curl -fsSL https://ollama.com/install.sh | sh`,
`ollama pull bge-m3`).

Системный `python3` не подойдёт: в нём нет ни Flask, ни MCP SDK.

## Если что-то пошло не так

| Симптом | Причина и что делать |
|---|---|
| плашка «эмбеддер … недоступен» | Ollama не запущена или нет модели: `ollama serve`, `ollama pull bge-m3` |
| сборка идёт минуты, а не секунды | поменялись параметры или документы — новые чанки считаются заново (bge-m3 на CPU ≈ 140 токенов/с) |
| «Индекс … собран эмбеддером …» при поиске | индекс собран другой моделью: пересоберите или выберите тот же эмбеддер |
| «Куда пойдёт?» отвечает «Маршрут (правила)» | модель маршрутизации не ответила (лимит провайдера) — это штатный запасной путь, выбор сделан по «темам» из `mcp-servers.json` |
| маршрут выбрал не те серверы | посмотрите описания в `mcp-servers.json`: по ним и выбирает модель. Можно назвать серверы руками в поле рядом с переключателем |
| «Инструменты MCP не включены» при запуске флоу | не включён переключатель «Давать инструменты модели» |
| флоу «оборван» | кончился бюджет (8 кругов / 12 вызовов). В итоге сказано, чего сделать не удалось; бюджет меняется ключами `--кругов-флоу` и `--вызовов-флоу` |
| шаг «отклонён» с «Сначала нужен вызов …» | так и задумано: правило порядка из `flow-rules.json` остановило вызов до того, как он изменил бы чужую систему |
| флоу «ждёт», а кнопки «Продолжить флоу» нет | сначала подтвердите или отклоните заявку в карточке «Заявки на изменение» |
| «Заявка №N ещё не решена» при продолжении | то же самое: флоу ждёт вашего решения, а не нажатия «Продолжить» |
| `tracker__get_issue` падает: «Трекер не отвечает» | не поднят мок: `.venv/bin/python tracker_api.py` во втором терминале |
| в отчёте текст вида «Выжимка: … Цифры: …» | модель не вызывалась: нет ключа или `PIPELINE_MODEL=нет`. Цифры важнее текста, поэтому шаг не падает |
| `ModuleNotFoundError: No module named 'flask'` или `'mcp'` | запущен системный `python3` — запускайте `.venv/bin/python` |
